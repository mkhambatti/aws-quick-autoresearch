The idea in one minute

Count once.
Check before you trust.

Imagine counting every item in a warehouse whenever someone asks what is on a shelf. A shelf-by-shelf tally could save time. But does it answer every question correctly? How long does it take to prepare?

This runner lets AWS Quick test those tradeoffs. Quick proposes the idea. The runner checks the answers, times the work, and returns the evidence. MCP is the connection between them.

A bounded experiment loop

The assistant proposes. The runner measures.

01 / DEFINE

Your questions

Register a snapshot, reference SQL, training cases, held-out cases, and a budget.

02 / PROPOSE

One testable idea

Quick submits SQL and an optional reusable summary with a stated hypothesis.

03 / VERIFY

Answers, then timing

The runner rejects mismatches and compares repeated candidate and incumbent timings.

04 / LEARN

Keep the evidence

Quick uses the result to choose its next trial. Finalization seals the run and opens held-out cases.

This is autoresearch: repeated experiments against a fixed evaluator. Inspired by Andrej Karpathy's autoresearch and the context post linked from his repository, this implementation applies the pattern to analytics instead of model training.

Bring your own data.

The small demo generates 2,400 synthetic order rows locally. No data download or AWS account is required. It checks the experiment loop; tiny-data speedups are not the claim.

git clone https://github.com/@@REPO@@.git
cd @@DIRECTORY@@
bash scripts/setup.sh
.venv/bin/quick-query demo-small

Use Python 3.11–3.13 on macOS or Linux. Your own CSV or Parquet goes in data/local/; private workload definitions go in workloads/local/. Both are excluded from Git.
