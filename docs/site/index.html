Experiment loop

Define
The owner registers a snapshot, reference SQL, training and held-out parameters, and a budget. The runner measures the baseline.
Propose
Quick submits a hypothesis, a complete set of queries, and an optional SQL statement to build a reusable summary.
Verify
The runner compares columns and row values on every training case. A mismatch rejects the candidate before benchmark timing. Passing candidates are timed against the incumbent.
Learn
Quick reads the decision and chooses the next trial. At finalization the runner seals the run, checks the winner on held-out cases, and records final speedup only after the checks pass.

Andrej Karpathy’s autoresearch loop varies training code and scores a model after training. Here the editable inputs are SQL and Parquet layout. The runner uses deterministic answer checks and repeated timing measurements to evaluate each change. Original project · Karpathy’s post · Technical design

Run the local demo

Use macOS or Linux with Git and Python 3.11–3.13. The scripted demo generates 2,400 order rows locally and runs without AWS credentials or a separate dataset download.

git clone https://github.com/@@REPO@@.git
cd @@DIRECTORY@@
bash scripts/setup.sh
.venv/bin/quick-query demo-small

Open the printed HTML report to see whether the summary helped and why dropping returned orders changed the answer. To test your own queries, put a CSV or Parquet snapshot in data/local/ and its workload definition in workloads/local/.
